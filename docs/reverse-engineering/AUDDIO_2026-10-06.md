## Evidence

Auddio publicly describes an iOS/TestFlight media center for audiobooks and podcasts with synchronized transcripts, local files, offline downloads, cross-device progress, chapters/bookmarks/shelves, listening stats, Up Next, playback speed, sleep timer, Hardcover integration and an addon protocol. Its public addon guide documents JSON-over-HTTP manifest/search/cache/resolve/progress/catalog concepts.

The public `ketanchoyal/auddio-addon-sdk` repository had no detected license metadata in the GitHub API snapshot used for this intake, so source is treated as research evidence only unless licensing is clarified.

The supplied Reddit thread was extremely fresh and exposed no substantive independent user feedback at the research snapshot. A related beta-test post asks whether onboarding is clear and whether live transcripts are useful; those are creator research questions, not independent feedback.

Comparators: Audiobookshelf validates the combined audiobook/podcast library, offline listening, progress sync and metadata/chapter category, but is server/self-host oriented. Metacast validates transcript-first navigation, search, bookmarks, playlists and creator transcript ingestion, and documents transcript-sync drift as a real failure mode.

## Clean-room boundary

Do not copy Auddio branding, layouts, private behavior, schemas, source or protected implementation structure. Public Auddio material also describes torrent/debrid discovery and resolution. That path is intentionally excluded from Afterlight Spoken Phase A. The initial product accepts user-selected local audio and user-selected transcript files only.

## Internal donor audit

Afterlight already owns browser audio playback, local playback memory, local queue/history, offline infrastructure, normalized library/provider concepts, responsive web surfaces, build/release verification and deployment plumbing. Creating a separate media-player repository would duplicate those capabilities. The canonical product implementation is therefore an additive `/spoken/` route in `afterlight-radio`.

## Product thesis

**Afterlight Spoken** is a calm, privacy-first shelf for spoken audio.

Primary workflow:

`select local audio → save metadata/progress locally → listen/resume → optionally import timed transcript → queue next item → reload → explicitly relink local file → resume`

Persistent metadata may survive reload, but the browser must never imply durable file access. Reloaded media transitions to `needs_relink` until the user selects the matching file again.

## Phase A behavior contract — `spoken-library/v1`

1. Accept `audiobook` and `podcast_episode` items.
2. Local files enter through an explicit browser file picker.
3. Runtime playback uses object URLs; object URLs are never persisted.
4. Persist metadata fingerprint, progress, duration, queue and listening seconds locally.
5. Matching file re-selection restores progress.
6. Up Next supports add/remove/reorder/play-next.
7. WebVTT and SRT imports validate timed, ordered, non-overlapping cues.
8. Plain text is readable but not represented as synchronized.
9. Timed cues highlight and seek during playback.
10. Playback speed is bounded to 0.5×–3.0×.
11. Sleep timer pauses playback; optional 30-second rewind applies once on resume.
12. Listening statistics derive from bounded media-time deltas rather than page-open wall-clock time.
13. Reloaded local items are `needs_relink`, never falsely `ready`.
14. Phase A runtime contains no network/upload primitive.

## Verification gates

The repository gate requires the build to emit `/spoken/index.html` and `/spoken-library.js`, validates browser-runtime syntax and contract markers, and rejects `fetch`, XHR, Beacon, WebSocket, FormData or `/api/` in the Phase A runtime. The normal `npm test` chain must invoke this gate.

Still required before production-readiness: exact-head CI, real browser local-audio/transcript flow, mobile viewport inspection, reload/relink/resume UAT, hosted Preview inspection, rights/accessibility review.

## Explicit non-claims

No Auddio parity. No native iOS/Android build. No Hardcover, RSS/OPML, AI transcription, server sync, torrent/debrid addons or Auddio protocol compatibility. No production certification until remaining evidence gates pass.
